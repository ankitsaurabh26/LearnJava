`DemoApplication.java` — The ignition key

- This is the entry point, like main() in any Java program
- `@SpringBootApplication` tells Spring to scan all files in the package and wire everything up
- Without this, the app won't start at all

`HelloController.java` — The traffic controller

- Listens for incoming HTTP requests
- `@RestController` marks it as a class that handles web requests
- `@GetMapping("/hello")` means "when someone does a GET request to /hello, run this function"
- Returns "Hello, World!" as the response

`ServletInitializer.java` — The deployment helper
- Only useful when you want to deploy your app as a WAR file to an external server like Apache Tomcat
- For local development it does nothing, you can completely ignore it
- It was auto-generated by `start.spring.io` because you selected WAR packaging

### Layered Architecture in Spring (Simple Overview)

<p align="center">
  <img src="../Images/Spring Boot Flow.jpg">
</p>

#### 1. Presentation Layer (Controller)

* Entry point of the application
* Handles **client requests (HTTP/JSON)**
* Converts request data into DTOs
* Sends response back to client

👉 Example: `@RestController`

#### 2. Service Layer (Business Logic)

* Contains core application logic
* Processes data received from controller
* Calls the persistence layer when needed

👉 Example: `@Service`

#### 3. Persistence Layer (Repository)

* Responsible for database operations
* Communicates with the database
* Uses entities to store/retrieve data

👉 Example: `@Repository`, JPA repositories

#### 4. Database

* Stores application data
* Accessed only through the persistence layer

## 🔄 Data Flow

1. Client sends request → Presentation Layer
2. Presentation converts request → DTO
3. Service Layer processes DTO
4. Persistence Layer interacts with DB using Entities
5. Response flows back in reverse order

#### 📦 DTO vs Entity

* **DTO (Data Transfer Object)**
  Used to transfer data between layers (safe, customizable)

* **Entity**
  Represents database table structure

#### 🧠 Simple Analogy

* Controller → Receptionist
* Service → Manager
* Repository → Clerk
* Database → Storage

This is the **standard design pattern used in most Spring Boot applications**.

#### Steps and Usages

- Create packages named: `controller`, `entity`, `service` and `repository`

 `Controller` layer will get all the requests.

 Model will be created using `service`; service internally will use `entity` and `repository` to generate model, thereafter the JSON will reach back to controller and then the view part will be created.

 - Create a `class` in controller - use `@RestController` annotation - create mapping inside the class using `@GetMapping("")`

 - create a package `DTO`, create a class file inside it named `StudentDto`

 - Add dependecies: `Spring Data JPA SQL` and `MySQL Driver`

 - For configuring the database to the code: Go to `resources` folder - `application.properties`
 ```
 # DataSource
spring.datasource.url=jdbc:mysql://localhost:3306/your_database_name
spring.datasource.username=your_username
spring.datasource.password=your_password
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

# JPA / Hibernate
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQL8Dialect
spring.jpa.properties.hibernate.format_sql=true
```

- Once the connection is setup with the database go to `entity` - create a new class file (say StudentA)- Add `@Entity` annotation over the class - this will create a table inside the database named `StudentA`

---

**Hibernate** is an **ORM** (Object-Relational Mapping) framework.

`Object` : The **Java part** (your `Student class`).

`Relational` : The **Database part** (your `student table`).

`Mapping` : The "bridge" that connects the two.

> Without Hibernate, you have to write long, repetitive SQL strings for everything.

Hibernate can look at your `Java classes` (with those `@Entity` and `@Id` tags we talked about) and **automatically create the tables** in MySQL for you. You don't even have to open MySQL Workbench to run CREATE TABLE!

---

- Now we can connect the `entity` with `controller` package but before that we have another layer called `repository` where we will be writing all the **QUERIES** if needed.

- Create a new `interface` file in the `repository` (say StudentRepository) that extends `JpaRepository` - takes two params inside `<table_name/class_name_mapped_to_table, datatype_of_id>` - has CRUD operations inbuilt

- Now we will `connect` the `repository` with the `controller`

- Go to controller file - add this line: `private final StudentRepository`

> Till now we have connected the persistance layer directly with the presentation layer - didn't use the service layer.

---

- Go to `service` package and make an interface (say StudentService)
- Create `another package inside the service package` name it Imp(implementation where all the implementations would be there)
- Inside Imp create a class (Say StudentServiceImplementation) and implement the service logic there, `return the data in dto` format using stream or loops. 
- Go to `controller` and then start the bean DI StudentService by `private final StudentService studentService;`

---

- We will use `ModelMapper library` to convert Student to StudentDto. For that after injecting the dependecy to the pom file we need to create a bean of ModelMapper - for that we will create a `config package` where we will be using all the configurations for such stuff.

```
// This is the second way of creating a bean; first way using @Component [stereotype]
@Configuration
public class MapperConfig {
    @Bean
    public ModelMapper modelMapper(){
        return new ModelMapper();
    }
}
```

#### Post Mapping

- Go to `controller` and create `@PostMapping`
- Create a new class file in `dto` package (say AddStudentRequestDTO)
- Go to `service` and add the function to the `interface` - then go to imp for `implementation` of the function

---

#### Put/Patch Mapping

- Full data change : Put
- Partial data change : Patch
